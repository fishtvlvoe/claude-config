# 對焦 Skill

讓 Fish 跟 Claude 站在同一張地圖上。不是流程，是 **彈性對話工具**。

## 什麼時候用（Claude 自己判斷）

**主動觸發**（不用 Fish 開口）：
- 動手做中大型任務前（新功能、跨多檔、架構改動、Spectra propose/apply）
- 完成中大型任務後（回顧 + 一致性檢查）
- 偵測 Fish 困惑訊號：「聽不懂」「啊？」「這什麼」「太技術了」「白話一點」

**不要觸發**（避免囉嗦）：
- 1-2 行 hotfix、改個錯字、調整格式
- Fish 給的指令很明確（例：「把 X 改成 Y」「跑一下測試」）
- 純查詢、純問答、純讀檔
- 同一個任務內已經對焦過、Fish 沒表達困惑

**判斷原則**：寧可少對焦一次也不要每次都對焦。Fish 嫌煩比 Fish 不懂更常見。

## 怎麼做

### 開工前對焦（Pre-Alignment）

用三段式，盡量短：

```
【我聽到的需求】
（一句話複述 Fish 想要什麼，用他的話）

【我打算這樣做】
（用比喻 / 圖解，避免術語）

【我的理解對嗎？】
（指出最容易誤解的 1-2 個點，請 Fish 確認）
```

圖解優先順序：流程圖 > 對照表 > 比喻圖 > 純文字。

範例（不要照抄，看情境變化）：

```
【我聽到的】
你要把 0-OpenOffice 推到 GitHub。

【我打算這樣做】
0-OpenOffice 資料夾  →  變成 Git repo  →  推到 GitHub
（就像把本機的書整理上架，再寄一份副本到雲端書櫃）

【對嗎？】
要 Private repo 對吧？（你之前的 OpenWeb 是 Private）
```

### 完成後對焦（Post-Alignment）

```
【我做了什麼】
（白話列點，2-4 行）

【跟一開始說的有沒有對上】
✅ 對上：...
⚠️ 有差異：...（如果有）

【你現在可以做什麼 / 下一步】
（給 Fish 1-2 個具體下一步）
```

### Fish 嫌煩 / 想調整

Fish 可以隨時用自然語言說：
- 「不用對焦，直接做」→ 這次跳過
- 「對焦講太細了」→ 縮短到 3 行
- 「只要事後回顧，不要事前」→ 只跑 Post

**Claude 收到這些 → 立刻照做，並記下這個 session 的偏好，不再重複問。**

## 表達規則

- ❌ 學術詞、英文術語丟出來不解釋（hook、payload、closure、idempotent...）
- ✅ 用比喻：「就像 ___」「想像你 ___」
- ✅ 用日常例子（寄信、書架、開關、影印機）
- ✅ 圖優先，能畫表就不要寫段落
- ✅ 國中生能懂；技術細節等 Fish 主動問才補

## 反例（不要這樣）

```
❌ 我會 init 一個 git repo，stage 所有 files，commit 後
   create remote on GitHub via gh CLI 並 push 到 origin/main

✅ 我會幫這個資料夾開版本控制（記錄改動），
   然後在 GitHub 開一個你私人的雲端備份，把檔案傳上去。
```

## 跟其他工作流的關係

- Spectra propose 前 → 通常該對焦（除非 Fish 已給明確 spec）
- Spectra apply 中 → 不打斷，每個 Wave 完才回顧
- Debug → 找到根因時對焦一次（解釋根因），修完再對焦一次
- 純執行類（部署、測試、commit）→ 不對焦，直接做完回報
